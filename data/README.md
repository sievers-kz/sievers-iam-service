# data/

## Что в папке
Сгенерированные данные, которые нужны сервису при запуске. Сейчас там один файл:
- `weak_passwords.bloom` — фильтр Блума со списком скомпрометированных паролей.

## Правила
- Файлы из этой папки не коммитятся в Git (в репозитории остаётся только этот README).
- Файлы не попадают в Docker-образ, а подключаются к контейнеру при запуске только для чтения.
- Исходный список паролей (txt) в проекте не хранится и в Git не кладётся.

## Как создать фильтр
Путь к результату задаётся переменной `BLOOM_PATH` в `.env` (пример значения — в `.env.example`).

Команда запуска:

```
just genbloom путь/к/списку.txt
```

Из WSL диск C: доступен как `/mnt/c/`, путь пиши в кавычках:

```
just genbloom "/mnt/c/Users/имя/Downloads/passwords.txt"
```

Что делает генератор (`cmd/bloomgen`):
- читает список построчно, одна строка — один пароль;
- пропускает строки короче 8 и длиннее 64 символов (такие пароли сервис всё равно не примет);
- строит фильтр с долей ложных срабатываний 1% (флаг `-fp`);
- записывает файл по пути из `BLOOM_PATH`.

## Как это работает
Фильтр Блума отвечает на вопрос «есть ли пароль в списке»:
- «нет» — пароля точно нет в списке;
- «да» — пароль, скорее всего, в списке. Примерно в 1% случаев фильтр может ошибиться и отклонить нормальный пароль, это допустимо.

Регистр учитывается как есть: `Password1` и `password1` — разные пароли.

## Если файла нет
Сервис при запуске пишет предупреждение в лог и работает без проверки по списку. Если файл есть, но повреждён, сервис не запускается.

После пересоздания файла сервис нужно перезапустить.
